# Van project rules

This repo is a custom Ford Transit 350 high-roof van plan. The pages are built from the sources in `tools/`; edit the sources, not the generated HTML.

- **Always show changes in all the html files when changes are made** (user rule). A change to the design goes into every page it touches: `interactive.html` (the adjustable plan, from `tools/ia_*.js`), `sides.html` (the static diagrams and tables, from `tools/gen2.py`, `plan.py`, `cur.py`, `ceiling.py`, `couch.py`, `leaf.py`, `shelf.py`, `couchmod.py`, `letters.py`, `trim.py` (the seven wall-trim drawings on the Walls page of the build guide); `tools/panpage.py` (the Shower pan page of the build guide: nine drawings, the parts and the steps; run by `buildguide.py`, not by `gen2.py`; the liner and drain numbers are also sizes in `ia_core.js`: `linerOn`, `linerT`, `linerTop`, `linerGap`, `pdrX`, `pdrY`, `headHole`, `valveHole`, so change both); the numbers of the raised couch, the gear shelf and the side window are shared in `shelfdata.py`; the furring dots, pieces, furring rail width (`STRIP_W` 3.5: the main furring rails S1 to S8 are 1x4; the window frame and nook frames stay 1x2, 1.5 wide; also `STRIP_W` in `ia_elev.js`; the code keeps the name STRIP_W). **Naming (user, 2026-10-28): the long boards are "furring rails", never just "strip" (a strip is also LED strip, steel strip, corner strip), and the pad, block and shim under them are "spacers"** and spacer block size (`SPC_*`: 1.5 x 3.5, 3 5/8 out) and the window frame are shared in `furring.py`, which `furrlist.py` turns into `furring-cut-list.md`, so edit those, not the list), `wall-map.html` (`tools/wallmap.js`), `electric.html` (`tools/electric.js`), `interior.html` (the 3D view, `tools/interior.js` and `interior_scene.js`) [ON HOLD, see the 3D bullet below], `install.html` when its numbers change (`tools/install.py`), and `site/` (`make-site.py`). `site/build/` is the build guide: one page per part of the build in order (`tools/buildguide.py`, run by `make-site.py`; it reads `sides.html`, `tools/plan_rows.json`, `tools/build_steps.json` and `furring-cut-list.md`), so a new part of the build goes in the list in `buildguide.py` too. Then update every published artifact link (the plan page comes from `tools/artmain.py` and is published with the whole of `site/` as its files; the 3D (skip it while it is on hold), electrical and wall-map pages come from `node tools/interior.js` with `SC` set to the scratchpad, and `tools/artfrag.py electric|wallmap`), and commit and push.

Until the user says to make it: do NOT edit `tools/interior.js` or `tools/interior_scene.js`, do NOT commit a regenerated `interior.html` or `site/interior.html` (`sh tools/build.sh` rewrites both, so right after a build run `git checkout -- interior.html site/interior.html`), and do NOT republish the 3D artifact. - Rebuild with `sh tools/build.sh` (do not pipe it through head).
- Add an entry to `van-notes.md` for every change.
- Never make the repo public: the top-level `photos/` has GPS data. Only `site/` (photos with the metadata stripped) is meant to be published.
- Commit on the working branch and push there; do not open pull requests unless asked.
