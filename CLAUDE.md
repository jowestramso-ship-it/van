# Van project rules

This repo is a custom Ford Transit 350 high-roof van plan. The pages are built from the sources in `tools/`; edit the sources, not the generated HTML.

- **Always show changes in all the html files when changes are made** (user rule). A change to the design goes into every page it touches: `interactive.html` (the adjustable plan, from `tools/ia_*.js`), `sides.html` (the static diagrams and tables, from `tools/gen2.py`, `plan.py`, `cur.py`, `ceiling.py`, `couch.py`, `leaf.py`, `shelf.py`, `rail.py`, `letters.py`; the numbers of the raised couch and the gear shelf are shared in `shelfdata.py`), `wall-map.html` (`tools/wallmap.js`), `electric.html` (`tools/electric.js`), `interior.html` (the 3D view, `tools/interior.js` and `interior_scene.js`), `install.html` when its numbers change (`tools/install.py`), and `site/` (`make-site.py`). `site/build/` is the build guide: one page per part of the build in order (`tools/buildguide.py`, run by `make-site.py`; it reads `sides.html`, `tools/plan_rows.json`, `tools/build_steps.json` and `furring-cut-list.md`), so a new part of the build goes in the list in `buildguide.py` too. Then update every published artifact link, and commit and push.
- **The 3D view is no longer on hold.** The user said 'Leave 3d view until I say to make it', then asked 'show me how the lift-out rail will work via 3d' (2026-10-26), so `interior.html` (`tools/interior.js`, `tools/interior_scene.js`) follows the rule above again. It now shows the raised couch, the open front under the deck, the battery, the wheel well, the lawn chairs and the gear shelf with an animated lift-out rail (a Play button and a slider).
- Rebuild with `sh tools/build.sh` (do not pipe it through head).
- Add an entry to `van-notes.md` for every change.
- Never make the repo public: the top-level `photos/` has GPS data. Only `site/` (photos with the metadata stripped) is meant to be published.
- Commit on the working branch and push there; do not open pull requests unless asked.
